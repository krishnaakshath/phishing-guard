# Phishing Guard v3 Overhaul — Implementation Plan

> **Note on granularity:** given the scope (new backend modules, full dashboard
> rewrite, extension redesign, new admin page) this plan uses coarse,
> deliverable-sized tasks rather than atomic 2-5 minute TDD steps, per explicit
> user priority on shipping fast. Each backend module still ships with real
> pytest coverage. Frontend tasks are verified by build success + manual
> smoke-test instructions, not exhaustive component tests.

**Goal:** Upgrade Phishing Guard from heuristic-only detection with a
disconnected dashboard into a real threat-intel-backed security tool with a
working multi-user dashboard, a new admin panel, and a redesigned UI across
extension + dashboard.

**Architecture:** Extend the existing Flask/SQLite backend, React/Vite
dashboard, and Manifest V3 extension in place. No framework changes.

**Tech Stack:** Python/Flask/SQLite (backend), React/Vite (dashboard),
vanilla JS Manifest V3 (extension). New deps: `flask-limiter`, `requests`
(already present). No new heavy deps (no Redis, no Postgres migration this
round — SQLite + Render persistent disk).

**Spec:** design agreed in conversation (see session summary above this
plan) — no separate spec file was written given the fast-moving scope.

## Global Constraints

- No Claude co-authorship trailer on any commit.
- Do not break existing `/api/scan`, `/api/batch-scan`, `/api/verify-site`
  response shapes — extension and dashboard both depend on them.
- All new public-facing checks (password breach, site scanner) must work
  with **zero required API keys** — Safe Browsing / VirusTotal keys are
  optional enhancements, feature must degrade gracefully (skip check, log
  warning) if the env var is unset.
- Admin endpoints must check `is_admin` server-side on every request — never
  trust a client-supplied role flag.
- Final step: commit locally per task, then push all to `origin/main` after
  a full review pass (build succeeds, backend imports cleanly).

## File Structure

**Backend (`backend/`)**
- `cache.py` — NEW. SQLite-backed TTL cache: `get_cached(key, ttl_seconds) -> dict|None`, `set_cached(key, data)`.
- `security_grade.py` — NEW. `grade_site(url) -> {grade, score, header_findings, tls_findings, cookie_findings}`.
- `breach_check.py` — NEW. `check_password_breach(password) -> {breached, count}` via HIBP k-anonymity range API.
- `secret_scanner.py` — NEW. `scan_for_secrets(html_text) -> [{type, match_preview, line}]`.
- `threat_intel.py` — MODIFY. Add `check_safe_browsing(url)`, `check_phishtank(url)`, `check_favicon_hash(url)`; wrap `_check_domain_age`/`_check_ssl_certificate` calls through `cache.py`.
- `models.py` — MODIFY. Add `is_admin` column (guarded `ALTER TABLE`), admin query functions: `list_all_users()`, `get_global_stats()`, `list_threat_reports()`, `verify_threat_report(id)`, `delete_threat_report(id)`.
- `app.py` — MODIFY. New endpoints (see Interfaces below), Flask-Limiter setup, CORS origin tightening via `ALLOWED_ORIGINS` env var.
- `requirements.txt` — MODIFY. Add `flask-limiter`.
- `tests/test_security_grade.py`, `tests/test_breach_check.py`, `tests/test_secret_scanner.py`, `tests/test_threat_intel.py` — NEW.

**Dashboard (`dashboard/src/`)**
- `api.js` — NEW. Single fetch wrapper: `apiGet/apiPost/apiPut/apiDelete(path, opts)`, attaches `X-API-Key` from localStorage.
- `AuthContext.jsx` — NEW. React context: `user`, `apiKey`, `login()`, `register()`, `logout()`, `isAdmin`.
- `pages/LoginPage.jsx`, `pages/RegisterPage.jsx` — NEW.
- `pages/DashboardPage.jsx`, `pages/HistoryPage.jsx`, `pages/WhitelistPage.jsx`, `pages/BlacklistPage.jsx`, `pages/SettingsPage.jsx` — extracted from current `App.jsx`, wired to real API via `api.js`.
- `pages/SiteScannerPage.jsx` — NEW. Public tool, no auth required.
- `pages/PasswordCheckerPage.jsx` — NEW. Public tool, no auth required.
- `pages/AdminPage.jsx` — NEW. Tabs: Overview (global stats), Threat Reports (moderate `threat_database`), Users (list). Route-guarded by `AuthContext.isAdmin`; redirects if not admin.
- `App.jsx` — REWRITE as router shell using `react-router-dom` (new dep).
- `theme.css` / `design-tokens.css` — NEW, from ui-ux-pro-max output.
- Remove inline `style={{...}}` blocks in favor of classes as pages are rewritten.

**Extension (`extension/`)**
- `config.js` — MODIFY. Convert to `export const CONFIG = {...}`.
- `background.js` — MODIFY. `import { CONFIG } from './config.js'`, add link-batch-scan call, site-grade fetch.
- `content.js` — MODIFY. Redesigned alert overlay (new visual language matching dashboard theme), site-grade badge, outbound-link risk highlighting, awareness-tip triggers.
- `popup.html/js/css` — REWRITE with new visual design, add "Check a password" / "Scan a site" links to dashboard tools.
- `manifest.json` — MODIFY. Bump to `2.1.0`.

## Interfaces (backend API contract — frontend/extension build against this)

```
POST /api/check-password-breach   (public, no auth)
  body: { "password": "..." }
  resp: { "breached": bool, "count": int }

GET /api/site-scan?url=<url>      (public, no auth)
  resp: {
    "url": str, "domain": str,
    "posture": { "grade": "A".."F", "score": 0-100, "header_findings": [...], "tls_findings": [...], "cookie_findings": [...] },
    "secrets": [ { "type": str, "match_preview": str, "line": int } ],
    "threat_intel": { "reputation_score": int, "threat_types": [...] }
  }

GET /api/admin/stats              (requires X-API-Key, admin only)
  resp: { "total_users": int, "total_scans": int, "total_threats": int, "reports_pending": int }

GET /api/admin/threats            (requires X-API-Key, admin only)
  resp: { "threats": [ { "id", "domain", "threat_type", "severity", "reported_count", "verified" } ] }

POST /api/admin/threats/<id>/verify   (requires X-API-Key, admin only)
DELETE /api/admin/threats/<id>        (requires X-API-Key, admin only)

GET /api/admin/users              (requires X-API-Key, admin only)
  resp: { "users": [ { "id", "email", "created_at", "last_login", "is_admin" } ] }
```

Existing endpoints (`/api/scan`, `/api/batch-scan`, `/api/verify-site`,
`/api/auth/*`, `/api/whitelist`, `/api/blacklist`, `/api/history`,
`/api/settings`, `/api/stats`) keep their current shapes — dashboard/
extension just need to actually call them.

## Tasks

### Task 1 — Backend: caching + real threat intel
Files: `cache.py` (new), `threat_intel.py` (modify), `tests/test_threat_intel.py` (new).
Deliverable: `threat_intel.check_url_safety()` now consults Safe Browsing
(if `SAFE_BROWSING_API_KEY` env set) and a cached PhishTank/OpenPhish feed
lookup, and WHOIS/SSL calls go through the cache with a 24h TTL. Missing
API keys must not raise — log and skip that check.
Test: mock the external HTTP calls; verify cache hit avoids a second call;
verify graceful skip when key is absent.

### Task 2 — Backend: new security modules + public endpoints
Files: `security_grade.py`, `breach_check.py`, `secret_scanner.py` (new),
`app.py` (modify — add `/api/check-password-breach`, `/api/site-scan`),
matching test files.
Deliverable: both new endpoints work against a real URL/password with no
auth required, per the Interfaces contract above.
Test: `breach_check` — use a known-breached test password hash prefix;
`secret_scanner` — feed it a string containing a fake `AKIA...` AWS key
pattern and confirm it's flagged; `security_grade` — mock `requests.get`
response headers and confirm grade logic.

### Task 3 — Backend: hardening + admin
Files: `models.py`, `app.py` (modify), `requirements.txt`.
Deliverable: rate limiting active on `/api/scan` and `/api/auth/*`;
`ALLOWED_ORIGINS` no longer defaults to `'*'` (default to the known
extension + dashboard origins, overridable via env); `is_admin` column
added; all `/api/admin/*` endpoints implemented and reject non-admins with
403 even with a valid API key.
Test: request `/api/admin/stats` with a non-admin key → 403; with an admin
key → 200.

### Task 4 — Dashboard: design system + routing shell (invoke ui-ux-pro-max)
Files: `theme.css`, `App.jsx` (rewrite), `AuthContext.jsx`, `api.js`.
Deliverable: `react-router-dom` routing shell, auth context wired to
`/api/auth/*`, new visual design tokens applied. Login/Register pages
functional end to end against the real backend.

### Task 5 — Dashboard: reconnect existing pages + new public tools
Files: `pages/DashboardPage.jsx`, `HistoryPage.jsx`, `WhitelistPage.jsx`,
`BlacklistPage.jsx`, `SettingsPage.jsx`, `SiteScannerPage.jsx`,
`PasswordCheckerPage.jsx`.
Deliverable: whitelist/blacklist/history/settings read and write through
the real API instead of local state; Site Scanner and Password Checker
pages call the new Task 2 endpoints and render results.

### Task 6 — Dashboard: Admin page
Files: `pages/AdminPage.jsx`.
Deliverable: overview stats, threat-report moderation (verify/delete),
user list — calling Task 3's admin endpoints, route-guarded client-side
*in addition to* the server-side check.

### Task 7 — Extension: redesign + feature wiring
Files: all of `extension/`.
Deliverable: popup and in-page alert visually redesigned to match the
dashboard's new theme; `config.js` actually imported and used; site-grade
badge shown per page; outbound link risk-scanning via `/api/batch-scan`;
contextual awareness tips on weak-password fields.

### Task 8 — Integration pass + push
Deliverable: `cd dashboard && npm run build` succeeds; `cd backend &&
python -c "import app"` succeeds with no import errors; extension loads
unpacked without console errors. Commit history is clean (no Claude
co-authorship trailer). Push to `origin/main`.
